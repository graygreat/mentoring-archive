## 세 가지 역할 설명

JPA는 객체 저장·조회·관리의 표준과 API이며, EntityManager 등의 실제 구현은 Hibernate 같은 JPA 구현체가 제공합니다. Spring Data JPA는 이를 이용하는 Repository의 반복 구현을 줄입니다. ProductEntity의 같은 ID 조회로 각 역할을 연결하고 EntityManager와 Hibernate를 별도 서비스 두 개처럼 설명하지 않습니다.

EclipseLink와 Apache OpenJPA도 JPA 구현체입니다. 표준 API를 사용하면 교체 영향을 줄일 수 있지만 설정·지원 표준 버전·생성 SQL·구현체 전용 기능을 확인하고 테스트해야 합니다. 이 수업에서는 Hibernate를 사용하며 다른 구현체 설치를 실습 과제로 추가하지 않습니다.

### 38. 직접 만든 Repository는 어디에 남을까?

기존 Repository 인터페이스를 유지하는 설계의 예입니다. Spring Data가 임의의 ProductRepository까지 자동으로 구현해 주는 것은 아닙니다. JpaProductRepository는 ProductRepository를 구현하는 직접 작성한 어댑터이고, ProductJpaRepository는 JpaRepository를 상속한 Spring Data 인터페이스입니다. 앞 장표의 Entity 직접 사용 코드는 학습용 축약이며 기존 Domain 분리 구조에 적용할 때 어댑터와 변환이 필요합니다.

### 39. save는 무엇을 할까?

Spring Data JPA 기본 상태 판단은 nullable 버전 필드를 먼저 보고 그 밖에 id를 검사합니다. Persistable 구현으로 바꿀 수도 있습니다. 이 장표는 예외 전략까지 외우기보다 persist와 merge의 객체 관리 차이를 이해하는 용도입니다.

### 40. 트랜잭션 설정에서 주의할 점

트랜잭션 기본 설명을 마친 뒤 필요한 경우 확인합니다. 자기 호출의 핵심은 프록시를 지나지 않는다는 점입니다. 기존 트랜잭션 참여와 독립적인 새 트랜잭션 시작도 구분합니다.
