# 2026-11-14 강사용 가이드 · 상품 CRUD 실습 6시간 + JPA 입문 2시간

책의 상품 관리 애플리케이션이 공통 수업 프로젝트입니다. 단축 URL은 별도 과제이며 수업 필수 진도를 대신하지 않습니다. 교재 CH 09 수정·삭제, CH 10 검증·예외, CH 12 추상화·테스트를 함께 읽습니다. CH 11 DB 연동은 JDBC 흐름과 JPA를 비교합니다. 책 본문과 쪽수를 확보하지 않았으므로 장 제목을 기준으로 수업 중 실제 절을 찾아 표시합니다. 제공 Java는 교재 복제가 아닌 독립 수업 예제입니다.

## 코드 계약과 실습 진행

기존 Java17 / Spring Boot4.1.2 / Gradle 프로젝트 product-api를 이어 사용합니다. Web MVC·Validation·AspectJ·기존 테스트 의존성을 유지합니다. 14일에는 JPA 의존성을 추가하지 않습니다.

기존 Product.java는 그대로 불변 객체를 유지합니다. 오늘 source-data는 ProductRepository, MemoryProductRepository, ProductService, ProductController, ProductCrudTest 다섯 파일입니다. ProductCrudTest는 신규 파일이며 기존 ProductServiceTest와 ProductWiringTest를 보존합니다. CreateProductRequest·ProductResponse·ApiExceptionHandler는12일 기준 파일을 유지합니다.

- PUT /products/{id}: 유효한 전체 이름·가격 변경200, 기존id 유지. 없는id404이며 새로 생성하지 않습니다.
- DELETE /products/{id}: 성공204/빈본문, 없는id404. 반복 후 최종 부재 상태를 근거로 멱등성을 설명합니다.
- Memory update는 computeIfPresent 안에서 검증된 새 Product로 교체합니다. 잘못된 변경은 기존 상품 값을 보존합니다.
- Service는 저장소의 Optional/boolean 결과를 도메인 예외로 변환합니다. 생성·수정 입력은 Service에서 Product로 먼저 검증하여 향후 @Repository 예외 번역이 도메인 IllegalArgumentException을 DB 예외로 바꾸지 않도록 합니다. Repository 인터페이스 책임을 유지합니다.
- @Valid와 기존 예외 처리기로400·404 응답을 유지합니다. 유효하지 않은 경로 타입 등의 모든 오류를 동일JSON으로 통일했다고 주장하지 않습니다.
- 이름·가격 검색 선택 과제 코드가 있으면 예제 전체 파일로 덮어쓰지 말고 수정점만 반영합니다.

먼저 요구사항만 보고 자율 구현합니다. 코드 슬라이드·파일 전체 모달은 막힌 지점 확인과 구현 뒤 비교에 사용합니다. 첫 줄·코드 계속 페이지의 들여쓰기를 임의로 정리하지 않습니다.

## 확인 절차

product-api에서 ./gradlew test / ./gradlew bootRun. Windows는 .\gradlew.bat test / .\gradlew.bat bootRun입니다. 기존 서버와 같은 포트가 충돌하면 기존 서버를 확인한 뒤 하나만 실행합니다.

1. 기존 생성·목록·단건·DTO검증·JSON오류·AOP 회귀 확인.
2. 실제로 상품 두개 생성하고 반환 id 기록. 특정 고정id나 연속id 가정 금지.
3. PUT 정상200, 같은id·변경값·공백strip·가격0 확인.
4. 빈이름·음수가격 PUT400 후 기존 값 보존. 없는id PUT404.
5. DELETE204·빈본문. 같은id GET/DELETE404. 다른상품 보존.
6. ProductCrudTest와 기존 단위/Wiring 테스트 통과 확인.

메모리 저장이므로 재시작 후 상품 소실이 현재 예상 동작입니다. JPA 전환 뒤 보존 검증은19일에 합니다. 재시작 보존을14일 필수 완료 기준으로 요구하지 않습니다.

## JPA 입문 활동

CH11의 JDBC 저장 흐름을 읽고 SQL 실행·결과 매핑·연결 관리 역할을 찾습니다. JPA는 객체-테이블 매핑과 영속성 컨텍스트를 제공하지만 SQL과 DB를 없애지 않습니다. ORM/JPA/Hibernate/Spring Data의 역할을 구분합니다.

docs/jpa-mapping.md 초안에 상품id·이름·가격·제약·생성주체를 기록합니다. 교재에 없는 제약은 수업 가정으로 표시합니다. @Entity/@Id/@GeneratedValue/기본생성자와 기존 도메인 규칙의 차이를 설명합니다. 오늘 Entity 완성·DB 전환은 필수가 아닙니다.16일에 실행 가능한 Entity와 Repository를 연습하고19일 실제 API를 전환합니다.
