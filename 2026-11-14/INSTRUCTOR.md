# 2026-11-14 강사용 가이드 · 상품 CRUD 실습 6시간 + DB 기초·JPA 맛보기 2시간

책의 상품 관리 애플리케이션이 공통 수업 프로젝트입니다. 단축 URL은 별도 과제이며 수업 필수 진도를 대신하지 않습니다. 교재 CH 09 수정·삭제, CH 10 검증·예외, CH 12 추상화·테스트를 함께 읽습니다. CH 11 DB 연동은 JDBC 흐름과 JPA를 비교합니다. 책 본문과 쪽수를 확보하지 않았으므로 장 제목을 기준으로 수업 중 실제 절을 찾아 표시합니다. 제공 Java는 교재 복제가 아닌 독립 수업 예제입니다.

## 코드 계약과 실습 진행

기존 Java17 / Spring Boot4.1.2 / Gradle 프로젝트 product-api를 이어 사용합니다. Web MVC·Validation·AspectJ·기존 테스트 의존성을 유지합니다. 14일에는 JPA 의존성을 추가하지 않습니다.

기존 Product.java는 그대로 불변 객체를 유지합니다. 오늘 source-data는 ProductRepository, MemoryProductRepository, ProductService, ProductController, ProductCrudTest 다섯 파일입니다. ProductCrudTest는 신규 파일이며 기존 ProductServiceTest와 ProductWiringTest를 보존합니다. CreateProductRequest·ProductResponse·ApiExceptionHandler는12일 기준 파일을 유지합니다.

- PUT /products/{id}: 유효한 전체 이름·가격 변경200, 기존id 유지. 없는id404이며 새로 생성하지 않습니다.
- DELETE /products/{id}: 성공204/빈본문, 없는id404. 반복 후 최종 부재 상태를 근거로 멱등성을 설명합니다.
- Memory update는 computeIfPresent 안에서 검증된 새 Product로 교체합니다. 잘못된 변경은 기존 상품 값을 보존합니다.
- Service는 저장소의 Optional/boolean 결과를 도메인 예외로 변환합니다. 생성·수정 입력은 Service에서 Product로 먼저 검증하여 향후 @Repository 예외 번역이 도메인 IllegalArgumentException을 DB 예외로 바꾸지 않도록 합니다. Repository 인터페이스 책임을 유지합니다.
- @Valid와 기존 예외 처리기로400·404 응답을 유지합니다. 유효하지 않은 경로 타입 등의 모든 오류를 동일JSON으로 통일했다고 주장하지 않습니다.
- 이름·가격 검색 선택 과제 코드가 있으면 예제 전체 파일로 덮어쓰지 말고 수정점만 반영합니다.

먼저 요구사항만 보고 자율 구현합니다. 코드 슬라이드·파일 전체 모달은 막힌 지점 확인과 구현 뒤 비교에 사용합니다. 첫 줄·코드 계속 페이지의 들여쓰기를 임의로 정리하지 않습니다.

## DB 기초·JPA 맛보기 활동

처음부터 영속성 컨텍스트와 ORM 용어를 나열하지 않습니다. 노트3000원으로 메모리 객체·JSON·표의 행을 먼저 비교합니다. 14일 필수는 종이·문서 기반 읽기와 예상입니다. Java 코드는 수정하지 않으며 JPA 의존성·DB 실행·Entity 완성을 요구하지 않습니다.

- 7교시: 설명10분(DB/DBMS·H2·메모리/파일·접속URL) → 상품 표 채우기20분(테이블/행/열·PK·자료형·NULL/빈문자열/0) → SQL 읽기15분(INSERT/SELECT/WHERE/ORDER BY).
- 8교시: 설명10분(트랜잭션·JPA의 역할·Entity/Id) → SQL 결과 예측·객체 매핑25분 → 동료 완료 확인10분.
- 매 블록 뒤15분 휴식·정리. 뒤2시간을 넘기지 않고 기존 추상 개념 설명을 이 활동으로 대체합니다. 영속성 컨텍스트의 상세 동작은23일에 관찰합니다.

[공통 DB 기초](../shared/db-basics/README.md)와 [멘티 작업지](../shared/db-basics/STUDENT-WORKSHEET.md)를 사용합니다. SQL을 재연습할 때는 공유 basics.sql의 별도 lab_products 학습용 표만 사용하며 실제 product-api 상품 데이터는 건드리지 않습니다. 수정·삭제 전 같은 WHERE의 SELECT로 대상 확인 → 예상 → 실행 → 재조회 순서입니다. WHERE가 빠지면 전체 행에 영향을 줄 수 있음을 말하게 합니다. ORDER BY 없이 행 순서는 보장하지 않습니다.

메모리 DB도 DB이며 파일 DB만 이번 수업의 재시작 보존 실험에 사용합니다. H2 접속URL은 HTTP URL이 아니고 상대 파일 경로는 실행 폴더에 영향을 받습니다. 파일을 직접 편집하지 않습니다. DB는 데이터 모음, DBMS는 관리 프로그램, H2는 이번 DBMS입니다.

PK는 중복·NULL 불가, NOT NULL은 빈 문자열·공백·음수를 전부 막는 규칙이 아닙니다. 이름·가격 규칙은 API/도메인 검증과 DB 제약이 보완합니다. id는16일 생성 전략에 맡기며 연속번호·재사용을 약속하지 않습니다.

트랜잭션은 한 묶음의 성공COMMIT/미확정 변경 취소ROLLBACK입니다. HTTP400을 반환하는 행위만으로 DB롤백이 보장되지 않고, 이미COMMIT한 변경은 나중ROLLBACK으로 취소되지 않습니다. Spring의 경계와 예외는16일에 실제 확인합니다.

JPA는 DB를 대체하지 않고 매핑을 이용해 SQL 실행을 돕습니다. @Entity는 표에 매핑할 클래스, @Id는 식별 필드라는 두 가지 역할부터 익힙니다. Product 도메인과 Entity를 분리하는 현재 구조를 유지합니다. 생성자·자동ID·Repository는16일 단계별 연습입니다. FK는 다른 표id를 참조하는 규칙으로 다음 관계 실습을 예고하는 정도만 합니다.

docs/jpa-mapping.md 초안에 상품 표·자료형·기본키·필수 여부·객체 대응, SQL 예상 결과와 확인, 틀린 이유를 기록합니다. 교재에 없는 길이·정책은 수업 가정으로 표시합니다. 종이 결과를 사진으로 기록해도 됩니다.16일 SQL과 JPA를 단계별 연습하고19일 실제 API 저장소를 전환합니다.
