# 프론트 생성용 AI 프롬프트

먼저 design.md의 API 계약을 실제 구현과 맞춥니다. 꺾쇠 항목을 채운 뒤 사용합니다. 이 프롬프트는 프론트만 생성하며 백엔드 정답은 요구하지 않습니다.

```text
내가 구현한 단축 URL 백엔드에 연결할 프론트를 만들어줘.
HTML, CSS, 순수 JavaScript만 사용하고 외부 라이브러리/CDN은 쓰지 마.
Spring Boot의 src/main/resources/static/index.html, styles.css, app.js로 제공해줘.
같은 origin에서 상대 경로 fetch를 사용해. 별도 서버·CORS 설정은 만들지 마.

아래는 실제 구현한 API 명세야. 필드·경로·응답을 임의로 바꾸지 마.
- 생성 메서드/경로: <직접 작성>
- Content-Type/요청 JSON: <실제 예>
- 성공 상태/헤더/JSON: <실제 예>
- 오류 상태/JSON: <실제 예>
- 원본 이동 경로와 상태/Location: <직접 작성>
- 화면에서 사용할 단축 URL 조립 규칙: <직접 작성>

화면은 원본 URL 입력, 생성 버튼, 로딩 표시, 생성 결과,
복사 버튼, 원본 이동 링크, 이해 가능한 오류 메시지를 포함해줘.
fetch는 HTTP 오류도 확인하고, 네트워크 실패와 JSON 읽기 실패를 처리해줘.
요청 중 중복 전송을 막고 성공·실패 뒤 버튼 상태를 복구해줘.
navigator.clipboard 실패 시 결과 텍스트를 수동 복사하도록 안내해줘.
사용자 입력/응답 URL/오류는 textContent로 표시하고 innerHTML에 넣지 마.
링크는 http/https URL인지 검사하고 javascript/data/file 스킴은 허용하지 마.
폼 label과 상태 메시지 aria-live를 제공하고 작은 화면에서도 동작하게 해줘.
원본 이동은 사용자가 링크를 클릭하게 하고 fetch로 리다이렉트를 따라가지 마.
서버에서 원본 URL 내용을 fetch하거나 미리보기 기능을 추가하지 마.
로컬 학습용으로 만들고 공개 배포·외부 추적 도구는 추가하지 마.
백엔드 Java 코드는 생성하지 말고 프론트 파일과 확인 방법만 알려줘.
```

## 멘티가 직접 확인할 것

1. URL·HTTP 메서드·JSON 필드가 실제 서버와 같은가?
2. 응답이 성공인지 어디서 판단하며 화면에 어떤 필드를 쓰는가?
3. 로딩·오류·복사 실패에서 어떤 코드가 실행되는가?
4. 위험한 링크 스킴과 HTML 삽입을 어떻게 막는가?
5. 실제 브라우저와 테스트로 무엇을 확인했는가?
