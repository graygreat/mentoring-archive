14일 오후 3시간 동안 교재 CH 14의 과제 테스트를 개인별로 풉니다. 저자 공식 시작 코드 14-1을 사용합니다. 문제 설명과 시작 코드는 확인하되, 교재 해설과 완성 코드를 최대한 보지 않고 설계·구현합니다.

14일 수업 자료

준비

개인 Fork의 sesac-spring-boot-study/order-api/에 시작 프로젝트를 둡니다. 시작 코드에 준비된 상품과 상품 API를 확인하고 주문 Domain·Repository·Service·Controller를 구현합니다. 책 예제 환경과 본인 Java·Spring Boot 환경이 다르면 먼저 실행 가능한지 확인합니다. 기존 product-api·personal-project·short-url은 보존합니다.

교재 요구사항 요약

API구현할 동작
POST /orders여러 상품과 수량으로 주문 생성. 재고 차감. 최초 상태 CREATED
PATCH /orders/{orderId}주문 상태 강제 변경
GET /orders/{orderId}주문 단건 조회
GET /orders?state={state}해당 상태의 주문 목록. 없으면 빈 배열
PATCH /orders/{orderId}/cancelCREATED 상태에서만 취소. 삭제하지 않고 이후에도 조회 가능

주문 응답에는 주문번호·주문상품·총액·상태를 포함합니다. 주문 상품의 이름·가격은 주문 시점 값으로 보존합니다. 없는 상품 또는 재고 부족으로 생성에 실패하면 주문을 만들지 않고 모든 상품의 기존 재고를 보존합니다. 상품 두 개 중 뒤의 상품이 실패할 때도 앞 상품 재고가 줄어들면 안 됩니다.

주문 생성 본문은 상품별 id·amount 객체를 담은 배열입니다. 응답은 id, orderedProducts(상품별 id·name·price·amount), totalPrice, state를 사용합니다. 상태 값은 CREATED·SHIPPING·COMPLETED·CANCELED이며 상태 변경 본문은 state 필드를 갖는 객체입니다.

정확한 JSON 필드와 입출력은 시작 코드의 README에 있는 계약에 맞춥니다. 이름을 임의로 바꿔 테스트와 맞지 않게 만들지 않습니다. 없는 상품·주문은 404입니다. 교재 문제는 재고 부족과 취소 불가능 상황에 500을 지정합니다. 이는 교재 과제의 응답 계약이며, 일반 서비스의 모든 업무 오류를 500으로 처리하라는 뜻은 아닙니다. 이번 기본 구현은 해당 계약을 지키고, 다른 코드가 적합한지는 별도 토론합니다.

취소 시 재고 복구는 교재 기본 요구에 명시되지 않습니다. 상태 강제 변경에도 임의의 상태 전이 제약을 붙이지 않습니다. 추가 정책을 만들면 기본 요구와 구분합니다.

구현 순서

  • 상품과 주문 데이터, 각 계층의 책임, API 입출력을 정리합니다.
  • 주문 생성과 단건 조회를 먼저 연결합니다.
  • 재고 차감과 주문 시점 정보 보존을 구현합니다.
  • 상태 변경·상태 조회·취소를 구현합니다.
  • 직접 QA 체크리스트를 작성하고 중요한 규칙을 테스트합니다.

완성본을 먼저 찾기보다 실패하는 입력·기대·실제 결과를 정리해서 질문합니다. DB와 JPA는 이번 문제의 필수 조건이 아닙니다. 메모리 구현으로 규칙을 먼저 완성해도 됩니다. JPA 입문 시간에 두 과제를 모두 JPA로 바꾸지는 않습니다.

추가 과제 · 선택

기본 요구를 완료했다면 중복 상품 요청·수량 검증 정책을 정하거나 주문 취소 시 재고 복구를 추가할 수 있습니다. 어떤 상태에서 복구하고 반복 취소를 어떻게 막을지 먼저 정합니다. 기본 요구와 다른 부분을 README에 명시합니다.

AI로 프론트를 만들 수도 있습니다. 순수 HTML·CSS·JavaScript만 사용하고 외부 라이브러리·프레임워크·CDN은 사용하지 않습니다. 프롬프트는 자율입니다. 실제 API에 연결하고 확인할 항목을 직접 QA 체크리스트로 작성합니다.

제출과 공유

브랜치 이름은 자율입니다. 공용 저장소에 Issue를 작성하고 개인 Fork origin에 Push한 뒤 원본 main을 base, 개인 Fork 작업 브랜치를 head로 PR을 제출합니다. PR에는 관련 Issue #번호·완료 기능·테스트 결과·미완료 범위를 적습니다. 수정은 같은 브랜치에 Push하며 강사가 병합 없이 PR·Issue를 닫습니다.

README에 환경·실행 방법·설계 결정·확인 결과를 기록합니다. 코드·Gradle 설정·Wrapper는 포함하고 build/.gradle/IDE/.env·비밀값·로컬 DB 파일은 제외합니다. 발표용 PPT 없이 코드와 실행 결과로 구현과 해결 과정을 설명합니다.
