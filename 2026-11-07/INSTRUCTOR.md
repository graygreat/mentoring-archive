## 개인 과제 · 취미 위시리스트와 예산 추천

구매하거나 체험하고 싶은 책·게임·운동용품·캠핑장비 중 주제를 고릅니다. `personal-project/`의 `CollectionItem(id, name, price)`를 중심으로 등록·전체 목록·id 단건 조회·예산 추천을 작성합니다. 이 요구사항은 교재 원문이 아니라 수업용 적용 과제입니다. 필수 규칙과 입력·출력 예시는 PPT에 직접 제시합니다.

- 이름은 null·빈 문자열·공백만 있는 값을 거부하고 앞뒤 공백을 제거합니다.
- 가격은 0 이상의 정수이며 무료 아이템을 허용합니다.
- id는 프로그램이 부여하고 등록 결과의 실제 id로 조회합니다. 없는 id는 예외로 구분합니다.
- 예산은 0 이상입니다. 각 아이템의 개별 가격이 예산 이하인 구매 후보를 가격 오름차순, 같은 가격은 등록 순서로 최대 3개 추천합니다.
- 추천 결과가 없으면 빈 목록, 예산 0이면 무료 항목만 반환합니다. 추천 조회가 원본 목록을 바꾸지 않아야 합니다.
- Repository 인터페이스와 메모리 구현을 나누고 Service가 생성자로 인터페이스를 받습니다.
- 정상·입력 실패·추천 경계·정렬·최대 3개·빈 결과·원본 보존을 포함한 단위 테스트를 최소 4개 작성합니다.
- Spring이 Service와 Repository를 실제로 연결하는지 통합 테스트나 실제 빈 실행으로 별도 확인합니다.

구현 및 준비는 150분입니다. 진행 중 오류가 생기면 재현 입력과 실제 결과를 정리합니다. 기본 과제는 Java 객체와 테스트까지이며 HTTP·DB·프론트 구현을 강제하지 않습니다. 발표용 PPT 대신 코드·테스트·실행 화면을 준비합니다. 미완료 교육생도 완료 범위와 막힌 지점을 설명합니다.

## 추가 과제와 AI 프론트

기본 과제를 끝낸 교육생은 이름 부분 검색, 즐겨찾기 또는 구매 완료 상태, AOP 실행 시간 로그 중 원하는 기능을 추가할 수 있습니다. 새 규칙을 정해 README에 적고 기존 테스트와 추가 테스트를 함께 실행합니다.

프론트는 AI를 활용하되 프롬프트는 자율입니다. 순수 HTML·CSS·JavaScript만 사용하고 외부 라이브러리와 CDN은 사용하지 않습니다. 등록 폼·목록·예산 입력·추천 결과를 구현합니다. 먼저 샘플 데이터로 화면을 만들 수 있으며 이때 샘플임을 표시합니다. 실제 연동을 선택하면 책 9장의 REST 부분을 자율적으로 참고해 HTTP API를 추가하고 fetch로 연결합니다. Java Service를 브라우저에서 직접 호출하는 구조로 설명하지 않습니다. 백엔드 핵심 로직은 직접 작성하고, AI가 만든 프론트도 직접 실행하고 설명합니다.

Initializr에서 만든 프로젝트는 내용물을 personal-project/에 복사하고 내부 .git은 제외합니다. 이전에 따로 만든 개인 저장소가 있다면 파일을 Fork의 해당 폴더로 옮기고 기존 기록은 보존합니다. force push로 이력을 맞추지 않습니다. 개인 Fork에 git push -u origin 본인브랜치로 올립니다.

### 20. 조직 원본으로 PR 제출

PR의 대상 저장소가 조직 원본인지, head가 본인 Fork와 작업 브랜치인지 확인합니다. PR 본문에는 구현 범위, 실행·테스트 결과, 관련 Issue 번호, 질문이나 미완료 범위를 적습니다. 관련 Issue는 같은 조직 원본의 #번호로 연결합니다. 자동 병합이나 Closes에 의한 자동 종료를 요구하지 않습니다. 제출 전 Files changed에서 비밀값·빌드 결과물·관계없는 수정이 들어가지 않았는지 확인합니다.

### 21. 리뷰와 제출 완료

교육생이 스스로 Merge하거나 리뷰 전에 PR을 닫지 않도록 안내합니다. 강사는 리뷰가 완료된 PR을 병합 없이 Close하고 관련 Issue도 수동으로 닫습니다. 수정 커밋을 같은 개인 Fork의 브랜치에 Push하면 열린 PR에 반영됩니다. 원본 main에 교육생별 코드를 병합하지 않으므로 다음 과제에서 이전 구현을 이어가면 새 PR에 이전 코드도 포함될 수 있습니다. 이전 PR을 링크하고 이번에 추가·수정한 범위를 구분해 기록합니다. 실행·테스트는 실제 구현이 있는 제출 브랜치에서 확인합니다.

### 22. REST API

기본 개인 과제에서 HTTP를 미리 구현할 필요는 없습니다. 먼저 끝낸 교육생의 프론트·API 연동은 선택 선행 과제입니다.
